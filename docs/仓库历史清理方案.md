# 仓库历史清理方案（规划，未执行）

现状（2026-10-24 测量）：`.git` 约 694 MB，当前 HEAD tree 仅 11.76 MB / 975 个文件，约 98% 体积是历史对象——早期把 `作品/`、部署包、`outputs/`、`参考资料/` 等大文件提交进了历史。对公开模板来说，clone 成本是采用的直接门槛。

清理会**改写全部历史**（所有 commit hash 变化），必须协调强推，先做不可逆操作前的备份。两个方案：

## 方案 A：git filter-repo 清理历史（保留提交历史）

1. `git bundle create backup.bundle --all` 全量备份，另存到仓库外；同时 `git clone --mirror` 一份冷备。
2. 安装 `git filter-repo`（`pip install git-filter-repo`）。
3. 在镜像克隆里执行路径删除（按 `git rev-list --objects --all | sort -k2` 实际确认清单）：
   `git filter-repo --invert-paths --path 作品 --path 参考资料 --path 上线交付 --path 网站部署文件 --path 逆向工程工具 --path-glob 'outputs/*' --path-glob 'backups/*' --force`
4. `git reflog expire --expire=now --all && git gc --prune=now --aggressive` 压缩对象。
5. 校验：新 `.git` 体积、`git log` 完整性、`npm run build:cloudflare` 全绿、`check:motion` 通过（确认没有登记文件被误删）。
6. 协调强推：`git push --force --mirror`；通知所有克隆者重新克隆（旧克隆无法快进）。
7. Cloudflare/GitHub 侧：确认 Pages/CI 从新历史重新部署；旧 commit 的 PR 引用会失效，属预期。

## 方案 B：当前 tree 新建干净仓库（推荐，更简单）

公开模板与私人作品彻底分家，历史一刀两断：

1. `git bundle` 备份旧仓库后归档（只读保留，不改名推送）。
2. 新目录 `git init`，把当前 HEAD 工作树（已通过全部检查）作为首次提交；LICENSE/NOTICE 与署名随 tree 保留。
3. 首提交信息注明「历史自 2026-10-24 的模板仓库迁移，旧历史见归档 bundle」。
4. 新仓库推送为新的公开模板源；旧仓库设为 archived 或私有。
5. 动效源码包（`build:motion-source`）与发布流程指向新仓库地址。

## 建议

方案 B：`.git` 从 694 MB 回到 12 MB 量级，一次到位，没有 filter-repo 的路径清单维护成本；模板使用者只需要最新 tree，不需要历史。方案 A 仅当「保留完整提交历史」是硬需求时选。

两个方案都需用户拍板后执行；执行前必须先完成 bundle 备份并确认 `outputs/`、`作品/` 等路径已在 `.gitignore`（2026-10-24 已补 `.mimosa/`）。
